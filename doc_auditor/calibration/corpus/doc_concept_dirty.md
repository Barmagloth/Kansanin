# Концепция платформы аналитики данных

## Обзор

Платформа предназначена для сбора, обработки и визуализации данных из различных источников,
включая транзакционные БД, потоки событий, файловые хранилища и т.д.

Основная идея: дать аналитикам удобный и быстрый доступ к данным без глубоких технических знаний.

## Проблематика

Текущие инструменты медленны, неудобны и требуют значительных усилий для настройки.
Аналитики тратят много времени на получение доступа к данным, их подготовку и прочие рутинные операции.

Если возможно, хотелось бы сократить время от запроса до инсайта с нескольких дней до часов.

## Ключевые принципы

1. Self-service: аналитик должен получить данные самостоятельно, без привлечения инженера.
2. Надёжность: платформа должна работать надёжно и предсказуемо.
3. Масштабируемость: по возможности, горизонтальное масштабирование.
4. Наблюдаемость: метрики, логи, трейсы и т.д.

## Архитектурные решения

### Хранилище данных

Используем колоночный формат (Parquet, ORC и т.п.) для аналитических запросов.
Горячие данные: оперативная БД. Холодные данные: объектное хранилище, если применимо.

Решение о конкретной технологии: TBD.

### Слой обработки

Spark или Flink — при наличии технической возможности.
Конкретный выбор зависит от нагрузки — см. раздел N.

### API-слой

REST API для интеграции с внешними инструментами, where applicable.
GraphQL — рассматривается, если это целесообразно.
